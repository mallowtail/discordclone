# Accounts Implementation Plan (short form — owner waived the full plan)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. The spec carries the detail; each task names the spec sections it implements.

**Goal:** Delete my account (Deleted User tombstones), transfer/delete server, 1–20 character usernames, Turnstile bot check.

**Spec:** `docs/superpowers/specs/2026-11-21-accounts-design.md` — binding; read it whole.

## Global Constraints

- Tombstone fields exactly as the spec's Design → Database step 4; display name "Deleted User".
- Refusal message (DB and UI mapping): `transfer or delete your servers first`. UI copy: "You own these servers. Pass on ownership to someone else (or delete the server) before deleting your account."
- Username format `^[A-Za-z0-9_]{1,20}$`; new usernames starting with `deleted_` refused.
- Owned servers block account deletion on every path (button, dashboard, admin API).
- Bot check: Turnstile site key from `NEXT_PUBLIC_TURNSTILE_SITE_KEY`; token passed as `options: { captchaToken }`; widget skipped when the env var is missing. Supabase CAPTCHA stays OFF until the owner enables it after deploy.
- Migrations: new file, dry-run then apply by hand via the Management API; production has real users (never touch them).
- Imports `@/…`; pure logic in `src/lib` with one test file per lib file in `tests/`.

## Review Focus

1. Deleting an account that is the last member of a group it owns → group removed, no error.
2. A 1:1 DM partner still sees the whole conversation, with "Deleted User" as the other side, and can't message/call them.
3. A dashboard/admin-API delete of someone owning a server is refused; of someone owning none, tombstones.
4. A 1-letter username works in @mention autocomplete, rendering and notifications.
5. With Supabase CAPTCHA on, change-password and delete-account confirmation still work.

### Task 2: App — usernames, Deleted User display, server transfer/delete, delete account

Build must pass; tests for any lib change.

### Task 3: Turnstile bot check
`Turnstile` component per spec; on register, login, and the password confirmations in Settings → Account (change password, delete account). Build must pass.

### Task 4: End-to-end, ship, enable
Local e2e (temp accounts via admin API): delete account (email user who owns a group; DM partner view), refusal with owned server (UI + admin API), transfer then delete, delete server (member's sidebar), 1-letter username + mention, Turnstile widget present (Cloudflare always-pass test key on localhost is fine). Full checks; final review; merge, deploy, prod e2e; then the owner enables CAPTCHA and sign-up/login/change-password are re-tested on production; clean up temp data.
